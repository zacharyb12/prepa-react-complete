# Context API

### Qu'est-ce que le Context API ?
Le Context API permet de partager des données entre plusieurs composants sans avoir à passer les props à chaque niveau (évite le "props drilling").

### Quand utiliser le Context API ?
- Données utilisées par plusieurs composants (utilisateur connecté, thème, langue)
- Éviter de passer des props sur plusieurs niveaux
- Gestion d'état global simple

---

## Créer un Context

### 1. Créer le contexte

```tsx
import { createContext, useContext, useState } from 'react';

// Définir le type des données
interface User {
  id: number;
  name: string;
  email: string;
}

interface UserContextType {
  user: User | null;
  setUser: (user: User | null) => void;
  isLoggedIn: boolean;
}

// Créer le contexte
const UserContext = createContext<UserContextType | undefined>(undefined);
```

### 2. Créer le Provider

```tsx
function UserProvider({ children }: { children: React.ReactNode }) {
  const [user, setUser] = useState<User | null>(null);

  const isLoggedIn = user !== null;

  const value = {
    user,
    setUser,
    isLoggedIn
  };

  return (
    <UserContext.Provider value={value}>
      {children}
    </UserContext.Provider>
  );
}
```

### 3. Créer un hook personnalisé pour utiliser le contexte

```tsx
function useUser() {
  const context = useContext(UserContext);
  
  if (context === undefined) {
    throw new Error('useUser doit être utilisé dans un UserProvider');
  }
  
  return context;
}

export { UserProvider, useUser };
```

## Utiliser le Context

### 1. Envelopper l'application avec le Provider

```tsx
// App.tsx
import { UserProvider } from './contexts/UserContext';
import Header from './components/Header';
import Dashboard from './components/Dashboard';

function App() {
  return (
    <UserProvider>
      <div className="app">
        <Header />
        <Dashboard />
      </div>
    </UserProvider>
  );
}

export default App;
```

### 2. Utiliser le contexte dans les composants

```tsx
// components/Header.tsx
import { useUser } from '../contexts/UserContext';

function Header() {
  const { user, isLoggedIn, setUser } = useUser();

  const handleLogout = () => {
    setUser(null);
  };

  return (
    <header>
      {isLoggedIn ? (
        <div>
          <span>Bonjour, {user?.name}</span>
          <button onClick={handleLogout}>Déconnexion</button>
        </div>
      ) : (
        <span>Non connecté</span>
      )}
    </header>
  );
}

export default Header;
```

```tsx
// components/Dashboard.tsx
import { useUser } from '../contexts/UserContext';

function Dashboard() {
  const { user, isLoggedIn } = useUser();

  if (!isLoggedIn) {
    return <div>Veuillez vous connecter</div>;
  }

  return (
    <div>
      <h1>Tableau de bord</h1>
      <p>Email : {user?.email}</p>
    </div>
  );
}

export default Dashboard;
```

## Exemple complet : Contexte de thème

```tsx
// contexts/ThemeContext.tsx
import { createContext, useContext, useState } from 'react';

type Theme = 'light' | 'dark';

interface ThemeContextType {
  theme: Theme;
  toggleTheme: () => void;
}

const ThemeContext = createContext<ThemeContextType | undefined>(undefined);

function ThemeProvider({ children }: { children: React.ReactNode }) {
  const [theme, setTheme] = useState<Theme>('light');

  const toggleTheme = () => {
    setTheme(theme === 'light' ? 'dark' : 'light');
  };

  return (
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      <div className={`app-${theme}`}>
        {children}
      </div>
    </ThemeContext.Provider>
  );
}

function useTheme() {
  const context = useContext(ThemeContext);
  if (!context) {
    throw new Error('useTheme doit être utilisé dans un ThemeProvider');
  }
  return context;
}

export { ThemeProvider, useTheme };
```

## Bonnes pratiques

### 1. Séparer les contextes par responsabilité
- Un contexte pour l'utilisateur
- Un contexte pour le thème
- Un contexte pour les notifications

### 2. Créer des hooks personnalisés
- Facilite l'utilisation
- Ajoute de la validation
- Centralise la logique

### 3. Éviter les contextes trop larges
- Ne pas mettre tout l'état de l'application dans un seul contexte
- Diviser en contextes plus petits et spécialisés

### 4. Optimiser les re-rendus
```tsx
// Séparer les valeurs qui changent souvent
const UserProvider = ({ children }) => {
  const [user, setUser] = useState(null);
  const [preferences, setPreferences] = useState({});

  // Diviser en deux contextes séparés si nécessaire
  return (
    <UserContext.Provider value={{ user, setUser }}>
      <PreferencesContext.Provider value={{ preferences, setPreferences }}>
        {children}
      </PreferencesContext.Provider>
    </UserContext.Provider>
  );
};
```

## Avantages et inconvénients

### ✅ Avantages
- Évite le props drilling
- Partage facile des données
- API simple et intégrée à React

### ❌ Inconvénients
- Tous les composants qui utilisent le contexte sont re-rendus
- Peut rendre les tests plus complexes
- Pas adapté pour un état très complexe

### 💡 Alternatives
- Pour un état complexe : useReducer + Context
- Pour des applications larges : Redux, Zustand
- Pour des données serveur : React Query, SWR
